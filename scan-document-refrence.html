01 The Pick — RFS 30 "Understand Before You Sign"
Submitted by

Prashanth Rao

Senior Director & India Product Head, Docusign. Solving a sponsor's own brief is the strongest possible demo alignment.

The one-line pitch

"X-ray your contract before you sign it."

Upload / pick an Indian contract → clauses light up red-amber-green on the page → hear it explained in Kannada, Hindi or Tamil → copy a WhatsApp-ready question for the landlord.

Positioning: "Everyone else builds a PDF chatbot. We built a machine that makes an unfair clause physically glow on the page — in your mother tongue."
Non-negotiable product rules
  • Zero chatbox — the document itself is the interface.
  • Verbatim grounding — the model may only quote exact substrings.
  • Fail-closed PII — Aadhaar, PAN, phone, names masked in-browser before any network call.
  • India-first benchmarks — a curated JSON of Indian norms is the moat.

04 Design system — tokens, components, motion, a11y
Colour — semantic, not decorative

Risk colour is a data channel, so it must never be the only channel. Every severity also carries a label + clause ID (WCAG 1.4.1).

Predatory --red
Negotiate --amber
Fair --green
Action --accent
Projector rule: default to Clean Light on stage — dark UI crushes on cheap projectors. Keep X-Ray Noir as a one-tap toggle for the deck.
Typography
  • UI: Inter / Geist — 12 / 13 / 15 / 20 / 28 / 40, tight tracking (−1.5%).
  • Data: JetBrains Mono for clause IDs (R1), scores, coordinates.
  • Number rule: safety score ≥ 19px, tabular figures.

05 PRD — problem, users, scope, metrics
Problem statement

Indian rental agreements, personal-loan T&Cs and offer letters are dense, English-heavy, and full of locally-normalised traps — a 10-month deposit, an 11-month lock-in that forfeits the deposit, unilateral 15% escalation, one-month painting deductions, bond clauses. People sign because reading them is expensive. Generic legal AI gives US-shaped advice.

Target users

First-time renter

22–28, Bengaluru / Pune / Hyderabad. Signing a leave-and-license this week.

Instant-loan borrower

Gig worker or salaried 25–35 taking a ₹50k–₹2L personal loan.

Fresher with an offer letter

22–24, first job. Training bond, IP clause, non-compete.

07 The Claude prompt (system + guardrails) 
You are SignClear, an Indian consumer-contract auditor.

INPUT
  <contract>   redacted text with [PERSON_1]/[AADHAAR_1]/[PHONE_1] tokens
  <benchmarks> indian_legal_benchmarks.json — the ONLY source of "normal"
  <doc_type>   rental | loan | offer

RULES
1. GROUNDING — every clause.verbatim MUST be an exact substring.
   If you cannot copy exact text, OMIT the clause. Never paraphrase.
2. NO LEGAL ADVICE — explain risk and what to ask.
   Use "unusual", "aggressive", "worth negotiating".
3. INDIA-FIRST — judge only against <benchmarks>.
4. SEVERITY — red = predatory; amber = negotiable; green = fair. Include ≥1 green.
5. PILLARS — exactly one of: financial_traps | lockin_exit |
   unilateral_rights | hidden_penalties | dispute_fairness
6. PLAIN SPEECH — ≤30 words, second person.
7. QUESTION — ≤25 words, polite, specific, WhatsApp-ready.
8. VOICE SCRIPT — 45–60s per language (en, hi, kn, ta). No bullets.
9. OUTPUT — JSON only, matching SCHEMA exactly.
10. If clean, say so: overall_score ≥ 80, verdict "safe". Do not manufacture risk.

SCHEMA
<insert locked JSON contract>
Why this wins: rules 1, 2 and 10 are the three things judges probe. Rule 1 kills hallucination, rule 2 kills liability, rule 10 kills the "AI that cries wolf" failure.

Scoring model
penalty = { red: 22, amber: 9, green: 0 }
pillarScore = clamp(100 - Σ penalty(clauses in pillar), 0, 100)

weights = { financial_traps:.30, lockin_exit:.25, unilateral_rights:.20,
            hidden_penalties:.15, dispute_fairness:.10 }

overall = round(Σ pillarScore × weight)
verdict = overall ≥ 80 ? "safe" : overall ≥ 50 ? "sign_with_caution" : "do_not_sign"
